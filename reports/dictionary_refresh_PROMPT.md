# Промт: обновление названий товаров Oriflame в справочнике

## Задача

У меня есть справочник товаров Oriflame — соответствие **кода товара** → **названию** → **категории**.
Часть названий некорректна: в исходном прайс-листе для многих кодов записано только
название оттенка/цвета (например, «Прозрачный беж»), без типа товара. Нужно найти
**полное официальное название товара** для каждого кода через веб-поиск.

## Входные данные

Файл: `dictionary_export.json` (6856 записей). Каждая запись:

```json
{
  "code": "21142",              // код товара Oriflame (строка/число)
  "current_name": "Прозрачный беж",  // текущее название (может быть только оттенком)
  "rubric": "Макияж",           // категория (закрытый список, НЕ менять)
  "conf": "medium",             // уверенность прошлого веб-поиска: high | medium | low | null
  "from_web_override": true     // true = имя уже искали в вебе; false = имя прямо из прайс-листа
}
```

Также есть CSV-версия: `dictionary_export.csv` (те же колонки, UTF-8 BOM для Excel).

## Что нужно сделать

Для КАЖДОГО кода:

1. **Веб-поиск** по запросу вида: `Oriflame <код> <current_name>` или `Oriflame артикул <код>`.
2. Найти **полное официальное название товара** — с типом продукта:
   - ✅ «Губная помада 100% цвета» (тип + линейка)
   - ✅ «Тушь для ресниц Wonderlash»
   - ✅ «Парфюмерная вода Amber Elixir»
   - ❌ «Прозрачный беж» (только оттенок — НЕ годится как финальное имя)
   - ❌ «21142» (только код)
3. Приоритет источников: **oriflame.ru**, официальные каталоги, сертифицированные
   сайты консультантов (kosmetista.ru, irecommend.ru — как вторичная проверка).
4. Если товар — **пробник/тестер**, отметить это в названии («… (пробник)»).
5. Если ничего достоверного не найдено — **оставить current_name без изменений**
   (лучше старое имя, чем выдуманное).

## Приоритет обработки (если ограничен по времени/бюджету)

| Приоритет | Фильтр | Кол-во | Почему |
|-----------|--------|--------|--------|
| 1 (высший) | `conf == "low"` | 36 | Самые сомнительные результаты прошлого поиска |
| 2 | `conf == "medium"` | 556 | Неполные названия (случай 21142) |
| 3 | `conf == "high"` | 1192 | Перепроверка ранее найденных |
| 4 (низший) | `conf == null` | 5072 | Имена прямо из прайс-листа — обычно уже корректны |

**Начни с приоритетов 1 и 2 (592 кода)** — там основная масса проблем.

## Формат вывода

Верни JSON-объект: код → новое полное название. **Только** те коды, где найдено
достоверное полное название (остальные пропусти — их имена останутся прежними):

```json
{
  "21142": "Губная помада 100% цвета — Прозрачный беж (пробник)",
  "11365": "Парфюмерная вода Amber Elixir",
  ...
}
```

## Требования к качеству

- **Не выдумывать** названия. Если не уверен — пропусти код.
- **Не менять** `rubric` (категорию) — она уже проверена отдельно.
- **Не менять** `code` — это неизменяемый идентификатор товара.
- Названия — на русском, как в официальном каталоге Oriflame РФ.
- Латинские названия линеек/ароматов оставлять как есть (Amber Elixir, Wonderlash,
  The ONE, Giordani Gold и т.п.).

## Как влить результат обратно в проект

Полученный JSON `{code: new_name}` сливается в `app/services/rubric_overrides.json`
(там формат `{code: {name, rubric, conf}}` — обновляется поле `name`, `conf`
поднимается до `high`). Затем перезагрузка БД:

```bash
uv run python scripts/import_master_pricelist.py
```

Скрипт применит `rubric_overrides.json` поверх прайс-листа и обновит таблицу
`dictionary` (6856 строк) в один проход, в одной транзакции — можно перезапускать.
