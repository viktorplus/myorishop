<objective>
Products can exist whose `code` has no matching row in the `dictionary` helper
table (imported dictionary data is incomplete, or a product was created with a
code the master price list never covered). Today the only way to add a
missing code is to manually retype it on `/dictionary`. This plan adds a
one-click backfill, reusing the existing `add_entry` write path (D-24: the
dictionary stays a helper — no FK, no ledger writes, no Product writes).

**Decisions locked for this plan** (per the constraints given):
- New page URL: `GET /dictionary/missing` (mirrors the `/dictionary` naming,
  reads as "products missing from the dictionary").
- No new router file — both new GET routes and both new POST routes are added
  to the existing `app/routes/dictionary.py`, which already owns "all
  dictionary reads" (see its module docstring) and now also owns this
  backfill-write surface, alongside the existing `add_entry`/`update_entry`
  POST routes.
- `dictionary.router` is wrapped with `require_role("administrator")` in
  `app/main.py` (unchanged) — every route this plan adds is therefore
  admin-only, exactly like the existing `/dictionary` CRUD.
- htmx response shape for the one-click action:
  - From the missing-products list: **whole-list re-render** — POST returns
    the SAME `partials/dictionary_missing_rows.html` partial, swapped
    `outerHTML` into `#dictionary-missing-rows`. The row "disappears" because
    the underlying LEFT JOIN query no longer returns that product, not
    because of a manual per-row DOM trick — this mirrors the existing
    `dictionary_rows.html` / `product_rows.html` idiom exactly.
  - From a product detail card: **small self-contained CTA swap** — POST
    returns `partials/dictionary_quick_add.html`, swapped `outerHTML` into
    `#dictionary-quick-add`, flipping the button into an "Есть в справочнике"
    done-state.

Two entry points are built:
1. `GET /dictionary/missing` — a dedicated page listing active products whose
   non-empty code has no matching dictionary row, reachable from the
   «Справочники» toolbar group on `/products` (desktop
   `app/templates/partials/products_toolbar.html` and mobile
   `app/templates/mobile_partials/products_toolbar.html`).
2. A one-click «Добавить в справочник» action on each row of that page AND on
   the product detail card (desktop `/products/{id}/edit`, mobile
   `/m/search/product/{id}`), creating the dictionary entry from the
   product's own code+name via `app.services.dictionary.add_entry`.

Purpose: let an administrator backfill missing dictionary rows in one click,
from wherever they notice the gap, without retyping code+name by hand.

Output: `list_missing_products` + `add_entry_from_product` service functions;
`GET /dictionary/missing`, `POST /dictionary/missing/{id}/add`,
`POST /dictionary/from-product/{id}` routes; the missing-products page + rows
partial + shared quick-add CTA partial; toolbar links on both desktop and
mobile; the CTA wired into the desktop product edit card and the mobile
product detail card, admin-gated cosmetically to match the real server-side
boundary; `__version__` bumped.
</objective>
