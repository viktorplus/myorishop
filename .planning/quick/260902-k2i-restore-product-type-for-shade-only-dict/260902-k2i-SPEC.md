# Восстановить тип товара у названий-оттенков — правила

## Проблема

В прайс-листе Oriflame тип товара пишется ОДИН раз, в первой строке серии, а
строки оттенков идут с ведущим дефисом:

```
33154  УВЛАЖНЯЮЩАЯ ТОНАЛЬНАЯ ОСНОВА THE ONE AQUA BOOST - ВАНИЛЬНЫЙ
33155  - ФАРФОРОВЫЙ
33156  - БЕЖЕВЫЙ НЮД
33157  - РОЗОВЫЙ НЮД
33158  - СЛОНОВАЯ КОСТЬ
33159  - ЕСТЕСТВЕННЫЙ БЕЖ
```

Импорт справочника взял строку буквально, и в базе у таких кодов осталось
только название оттенка: `33155` → «Фарфоровый». Пользоваться таким
справочником нельзя: по названию товар не найти, в описи он выглядит как
цвет без предмета.

## Масштаб (замерено, не оценка)

| | |
|---|---|
| Уникальных кодов в 232 прайс-листах | **12 492** |
| Кодов в справочнике | **12 582** |
| Есть в прайсах, нет в справочнике | **5** — все промо-строки, НЕ товары |
| **В справочнике стоит ТОЛЬКО оттенок** | **607** |
| Есть в справочнике, нет в прайсах | 95 (мастер-прайс и ручные записи) |

Из 607 попали в опись склада «Офис» пять: `32287`, `33155`, `33157`, `33158`,
`33159`.

**Добавлять в справочник нечего.** Пять «отсутствующих» кодов — это `0`, `1`,
`2`, `3`, `4`: текст акции, попавший в колонку кода
(«КУПИ ДЕТСКУЮ ЗУБНУЮ ЩЁТКУ + ПАСТУ ЗА 139 РУБ.»). Их вносить НЕЛЬЗЯ.
Справочник шире прайсов, потому что в него вошли ещё мастер-прайс и ручные
записи. Вся работа этой задачи — исправление 607 названий, а не пополнение.

**Наличие цены не является условием.** Позиция с кодом и названием попадает в
справочник независимо от того, заполнены ли ценовые колонки: сбор идёт по паре
«код + наименование». Именно поэтому в справочнике 12 582 записи, а строк с
ценами только 12 372.

### Осторожно с методикой подсчёта

Первый замер дал 298 вместо 607, потому что сверял имя справочника с одним
«лучшим» вариантом восстановленного имени. Это занижает: один и тот же код
бывает заголовком серии в одном прайсе и строкой-оттенком в другом. Верное
правило: имя в справочнике совпадает с оттенком **хотя бы одного** из
восстановленных вариантов, и существует вариант длиннее текущего имени.
Реализация обязана использовать именно его; расхождение с 607 — повод
остановиться и разобраться, а не подогнать.

Карта восстановленных имён — `full_map.json` (scratchpad), ключ `shade_only`.
Скрипты-разведчики черновые, в репозиторий не идут; рабочую реализацию писать
заново по этим правилам.

## Алгоритм восстановления

Проход по каждому листу каждого прайса сверху вниз:

1. Строка, название которой НЕ начинается с дефиса (`-`, `–`, `—`), — заголовок
   серии. Запоминаем тип товара: часть названия ДО последнего ` - `, а если
   разделителя нет — всё название целиком. Пример: из
   `УВЛАЖНЯЮЩАЯ ТОНАЛЬНАЯ ОСНОВА THE ONE AQUA BOOST - ВАНИЛЬНЫЙ` тип это
   `УВЛАЖНЯЮЩАЯ ТОНАЛЬНАЯ ОСНОВА THE ONE AQUA BOOST`.
2. Строка с ведущим дефисом — оттенок текущей серии. Полное имя =
   `<тип> - <оттенок>`.
3. Серия обрывается на следующем заголовке; в начале листа типа ещё нет —
   такие строки пропускаем.

## Две нормализации (решения приняты, не пересматривать)

**Написание типа — самое ПОЛНОЕ, а не самое частое.** Одна и та же серия в
разных прайсах пишется и как `ТОН. ОСНОВА`, и как `ТОНАЛЬНАЯ ОСНОВА`.
Сокращение встречается чаще, но в справочник должно попасть полное написание:
из всех вариантов для кода берём САМЫЙ ДЛИННЫЙ тип. При равной длине — самый
частый.

**Регистр — как у соседей по справочнику.** Прайсы в верхнем регистре, а
справочник ведётся в предложении: «Тональная основа «адаптив» - слоновая
кость». Значит первая буква заглавная, остальное строчными. Латиница внутри
(`THE ONE`, `SPF 30`) приводится по тому же правилу — так уже написаны
соседние записи («Туалетная вода soul»), единообразие важнее красоты.

## Что менять

**Только те 605 кодов, у которых в справочнике сейчас стоит ровно оттенок**
(имя точно равно хвосту восстановленного, без учёта регистра). Не трогать
записи, где название уже несёт тип товара, даже если прайс предлагает другое
написание: там правка может оказаться ухудшением.

Механизм — `app/services/rubric_overrides.json`: он ровно для этого и заведён,
его комментарий в `app/services/rubrics.py` говорит «для кодов, чьё имя из
прайса это только цвет/оттенок». Добавляем 605 записей; существующие 1 818 не
трогаем. Затем перевыгрузить `catalogs/products.json` (экспорт накопительный)
и перелить на s1.

## Чего НЕ делать

- Не менять названия, где тип товара уже есть.
- Не запускать полную замену справочника на s1: там 4 названия, вписанные
  руками, и правило оператора «при конфликте побеждает более полное серверное».
  Нужен аддитивный или точечный путь обновления ИМЕНИ существующей строки —
  `--only-missing` только вставляет и для этой задачи не годится. Способ
  предложить в плане.
- Ничего не запускать против s1 из этой задачи: выкатку делает оркестратор.
- Не переносить прайс-листы на сервер (118 МБ, вне git и вне образа по замыслу).

- На известной серии `33154`–`33159` восстановление даёт ожидаемые имена;
  проверено по двум независимым прайсам (`01-2018.xls`, `01-2019.xlsx`).
- Ни одно имя не стало КОРОЧЕ прежнего.
- Число изменённых записей ровно равно числу найденных «только оттенок».
- Полный `uv run pytest`; 4 падения `tests/test_sync_ui.py` известны, не чинить.
- Бампнуть `app/__init__.py`.
