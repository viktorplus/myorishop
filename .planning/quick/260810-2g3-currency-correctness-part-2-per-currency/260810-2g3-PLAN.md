<objective>
Currency correctness, part 2. Part 1 (commit cdcec66) added `Warehouse.currency`
(RUB/UAH/EUR, no conversion, no FX rate) but explicitly left reports/dashboard/
finance summing across warehouses with no currency dimension, sale baskets able
to mix batches from different-currency warehouses, and transfers not asking for
a destination-currency cost. This plan closes those four gaps, per the
operator's locked decisions in `.planning/ROADMAP.md` (Backlog, "Phase 999.1").

LOCKED (operator decision, added after initial planning — treat exactly like
the four decisions above, not as a suggestion): any Operation row that cannot
resolve a currency through a batch (`Operation.batch_id IS NULL` — the
pre-Phase-9 legacy rows) belongs to the RUB bucket, matching migration 0023's
backfill of every pre-existing warehouse to RUB (all pre-existing data has
always been RUB). This resolution — `Operation.batch_id -> Batch.warehouse_id
-> Warehouse.currency`, falling back to `DEFAULT_CURRENCY` when `batch_id IS
NULL` — is implemented as ONE shared helper, not re-implemented per report,
and MUST use an outer join (Batch, then Warehouse), never an inner join: an
inner join would silently DROP legacy rows from the RUB report instead of
counting them, which is a data-loss-shaped bug. `cash_movements.currency` is
backfilled to 'RUB' NOT NULL in migration 0024 for the identical reason — no
cash row is ever currency-less, so cash-side reports need no such fallback.

Money stays integer minor units everywhere — this plan adds NO FX rate, NO
conversion, NO base-currency roll-up, anywhere, ever. A currency filter always
resolves to exactly one currency (never "all"); every new `currency` parameter
added below is OPTIONAL and defaults to `app.core.DEFAULT_CURRENCY` ("RUB") so
every one of the ~130 existing call sites across services and tests that never
mention currency keeps compiling and passing UNCHANGED (they operate on RUB,
which is what all pre-existing data already is per the 0023 backfill) — only
NEW multi-currency tests need to pass `currency=` explicitly.

Output: cash movements, batch cost, sale baskets, transfers, /reports/sales,
/finance, the dashboard, and the CSV exports are all currency-correct; legacy
batch-less operations are counted under RUB rather than silently dropped; a
schema-mismatch push (new client field into an under-migrated server DB) fails
loudly instead of silently dropping data.
</objective>
