Это ровно та расходимость, которую фаза 33 зафиксировала осознанно (STATE.md,
33-14): маркер «задним числом» сравнивает `business_date` с ЛОКАЛЬНЫМ днём
`created_at`, а SQL-фильтр — с `substr(created_at,1,10)`, то есть с UTC-днём.
Прогон пришёлся ровно на окно расхождения:

```
now UTC   : 2026-09-07T21:56:50+00:00   UTC day   : 2026-09-07
now local : 2026-09-08T00:56:50+03:00   local day : 2026-09-08
STRADDLE (local day != UTC day): True
```

`same_day`-строка получает `business_date='2026-09-08'` при UTC-дне
`'2026-09-07'`, поэтому фильтр относит её к «задним числом» — тест краснеет.

**Доказательство, а не рассуждение:** те же 5 тестов запущены на ЧИСТОМ дереве
HEAD, развёрнутом через `git archive HEAD` в отдельный каталог (репозиторий при
этом не трогался — ни stash, ни reset). Пустое дерево подтверждено: ноль вхождений
`RECEIPT_SEP07`, `__version__ = "1.132"`. Результат — **те же 5 failed**. Мои
изменения там физически отсутствуют, значит причина не в них.

Тесты пройдут сами после 00:00 UTC. Это существующее свойство фазы 33, не дефект
