# Импорт полного архива прайсов в catalog_prices

## Что не так сегодня (замерено, не предположение)

`catalog_prices`: 15 798 строк, 12 372 кода, максимум **2** выпуска на код.
Это не история цен, а снимок мастер-прайса (одна строка на код,
«Последний каталог»). Архив `catalogs/price_lists` (233 файла: 118 `.xls` +
115 `.xlsx`) в эту таблицу не попадал никогда.

Полный обход архива даёт **237 913 строк / 227 выпусков / 11 557 кодов**,
из них 233 346 с ББ (в базе `points` NULL у всех 15 798 строк).
Троек `(year, number, code)`, которых в базе нет: 223 386.
Кодов, которых в базе нет вовсе: 74.

Видимое следствие: `/catalogs/{code}` берёт цены через
`prices_for_catalog(year, number)` и показывает «—» почти для всего
ассортимента выпуска — в таблице лежат только коды, для которых этот выпуск
оказался ПОСЛЕДНИМ.

### Корневая причина — две программы владеют одной таблицей

1. `scripts/import_prices.py` (xlsx-путь) делает `DELETE` всей таблицы.
2. `scripts/import_master_pricelist.py` делает `DELETE` всей таблицы.
3. `scripts/import_prices.py --from-export` без `--only-missing` — тоже.

Кто запустился последним, тот и стёр чужое. Задача не будет держаться,
пока это не исправлено: `deploy/DEPLOY.s1.md` §4 предписывает запускать
мастер-прайс ПЕРВЫМ шагом чистой установки.

### Три отдельных дефекта в import_prices.py

- **D1.** `main()` на ценовом пути читает `folder.glob("*.xlsx")` — `.xls`
  не берётся. Функции `read_workbook_sheets()` и `price_list_files()` в этом
  же модуле уже читают ОБА расширения (их написали для `--restore-shades`);
  ценовой путь их просто не использует.
- **D2.** Дефолт `--dir catalogs` указывает на папку, где лежит ровно один
  xlsx — `oriflame_prices_with_calculations_fixed.xlsx`, чьё имя
  `parse_catalog()` не разбирает. Значит `uv run python
  scripts/import_prices.py` без аргументов СЕГОДНЯ удаляет 15 798 строк и
  вставляет 0. Живой фугас.
- **D3.** `--only-missing` фильтрует по КОДУ. Для истории цен это ровно
  неверный фильтр: код, уже известный из мастер-прайса, не получит ни одной
  исторической строки. На сервере (`DEPLOY.s1.md` §4.1) используется именно он.

## Что сделать

### 1. Принцип: источник владеет своими строками, а не таблицей

Ни один импорт больше не делает `DELETE` всего `catalog_prices`. Каждый
удаляет/обновляет только те тройки `(year, number, code)`, которые сам
записывает. `UniqueConstraint("year", "number", "code")` уже есть
(`app/models.py:333`) — это и есть ключ владения.

- `scripts/import_prices.py`, путь архива и путь `--from-export`:
  прочитать существующие тройки одним запросом, новые — `bulk_save_objects`,
  совпавшие — обновить (и только если поле реально изменилось).
  Ничего не удалять.
- `scripts/import_master_pricelist.py`: убрать
  `session.query(CatalogPrice).delete()`, заменить на удаление только своих
  троек (или тот же upsert). `Dictionary` продолжает замещаться целиком —
  это отдельная таблица со своими правилами, её не трогаем.
- `--only-missing` (фильтр по коду) оставить как есть: он документирован,
  покрыт тестом и остаётся осмысленным. Пре-существующее поведение не режем.

### 2. Читать оба расширения на ценовом пути (D1)

Ценовой путь переиспользует уже существующие `price_list_files()` и
`read_workbook_sheets()`. Новых читалок не писать.
`collect_from_xlsx()` соответственно перестаёт быть «xlsx» — переименовать
по факту и поправить докстринг.

`parse_catalog()` сейчас срезает только `\.xlsx$`. Для `.xls` это случайно
работает (в «.xls» нет цифр), но написать честно: `\.xlsx?$`.

Ожидаемые исходы обхода (проверено):
- нечитаем 1 файл — `12-2013.xls`, битый OLE2 («File is truncated, or OLE2
  MSAT is corrupt»). Он уже обрабатывается в `scan_shade_candidates`;
  ценовой путь должен так же пережить его и НАЗВАТЬ в отчёте, не падать.
- 2 файла без колонки ПЦ — `04-2024.xls`, `05-2024.xls` (только названия).
- 3 файла с неразбираемым именем — `oriflame_prices_compact.xlsx`,
  `oriflame_prices_with_calculations.xlsx`,
  `oriflame_prices_with_calculations_fixed.xlsx`.

### 3. Дефолт папки (D2)

`--dir` по умолчанию должен указывать на архив
(`catalogs/price_lists`), а не на `catalogs`. В модуле уже есть
`--price-dir` с этим же дефолтом для `--restore-shades` — два флага на одну
папку это дублирование; свести к одному.

Плюс защита ровно от того отказа, который существует сегодня: если обход дал
0 строк — выйти с ошибкой, ничего не записав.

### 4. Транспорт на сервер — gzip (решение оператора)

Архива на сервере нет и не будет (`.dockerignore` режет
`catalogs/price_lists/`). Полный экспорт — 41.7 MB JSON, gzip — **4.7 MB**
(в 8.8 раза меньше). Оператор выбрал gzip.

- `--export` и `--from-export` открывают `.gz` прозрачно по суффиксу
  (`gzip.open`), обычный `.json` продолжает работать.
- Накопительность `write_export()`/`merge_price_export()` сохраняется без
  изменений — она уже написана и покрыта тестами.
- `catalogs/catalog_prices.json` (2.89 MB) удалить в том же коммите и
  заменить на `catalogs/catalog_prices.json.gz`: два файла с одними и теми же
  данными — это второй источник истины. Новый файл — НАДМНОЖЕСТВО старого
  (объединение архива и снимка мастер-прайса), проверить это явно перед
  удалением: ни одна тройка старого файла не должна пропасть.
- Убедиться, что `.gitignore` и `.dockerignore` не режут `*.gz`
  (сейчас не режут — проверено).

### 5. Порядок работ

1. Тесты (RED) на новое поведение.
2. Правки трёх пунктов выше.
3. Локально: `uv run --with xlrd python scripts/import_prices.py`
   (архив, оба расширения) — ожидаем ~237 913 строк.
4. Локально: `--export catalogs/catalog_prices.json.gz`, проверить
   надмножество, удалить старый `.json`.
5. `deploy/DEPLOY.s1.md` §4 и §4.1 переписать под новый порядок и новый файл.
   Предупреждение «только с `--only-missing`» для цен снимается: путь стал
   неразрушающим. Для `import_catalogs.py` предупреждение остаётся.
6. Бампнуть `app/__init__.py`.

## Проверки (обязательные, не пожелания)

- Полный `uv run pytest`. Известные падения `tests/test_sync_ui.py` не чинить
  (гонка `_run_lock`, задокументировано).
- `catalog_prices` после локального импорта: > 230 000 строк, `points`
  заполнен более чем у 200 000 строк, кодов не меньше 12 372
  (снимок мастер-прайса не потерян).
- Ни один код, у которого цена была ДО импорта, не остался без цены ПОСЛЕ.
  Это отдельная проверка на множествах, а не «на глаз».
- `latest_price_for_code()` для нескольких кодов возвращает то же самое
  до и после (последний выпуск не должен уехать назад).
- Повторный прогон импорта архива вставляет 0 новых строк (идемпотентность).
- `--from-export catalogs/catalog_prices.json.gz` в чистую базу даёт то же
  число строк, что и обход архива.
- Страница `/catalogs/{code}` для выпуска из 2020 года показывает цены, а не
  «—» (проверить на живом локальном сервере, не в тесте).
