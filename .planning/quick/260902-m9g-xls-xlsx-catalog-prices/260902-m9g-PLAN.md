<objective>
Import the full price-list archive (233 files: 118 `.xls` + 115 `.xlsx`) into `catalog_prices`, and
stop the two importers from deleting each other's rows.

Purpose: today `catalog_prices` is not a price history at all - it is a 15 798-row snapshot of the
master price list, so `/catalogs/{issue}` shows a dash for almost every product of every issue. The
root cause is that THREE code paths delete the entire table, so whichever importer ran last erased
the other's work. The load-bearing idea of this task: **a source owns its own `(year, number, code)`
triples, not the whole table.** `UniqueConstraint("year", "number", "code")` (app/models.py:333) is
that ownership key and it already exists.

Output (PRICE-01..07):
- `upsert_price_rows()` - one bulk, no-delete writer shared by the archive path, the `--from-export`
  path and the master price list.
- The price path reads both extensions through the readers that already exist (PRICE-02, defect D1).
- `--dir` defaults to the archive instead of the folder holding one unparsable xlsx (PRICE-03,
  defect D2 - today a bare `python scripts/import_prices.py` deletes 15 798 rows and inserts 0).
- gzip transport: 41.7 MB of JSON becomes ~4.7 MB, `catalogs/catalog_prices.json.gz` replaces
  `catalogs/catalog_prices.json` after an explicit superset proof AND a scale round-trip (PRICE-05).
- The real local import, with the measured invariants of the SPEC checked by set arithmetic, not by
  eye (PRICE-07).

<interface_contract>
The API the three tasks agree on - Task 1 writes tests against exactly these names, Task 2 implements
exactly these names.

In `scripts/import_prices.py`:

- `upsert_price_rows(session, records: list[dict], chunk: int = 5000) -> dict[str, int]`
  `records` are the existing 7-key export shape (`EXPORT_KEYS`). Returns
  `{"inserted": n, "updated": n, "unchanged": n}`. Never deletes, never commits.
- `collect_prices_from_sheets(sheets) -> dict[str, dict]` - pure; one workbook's sheets to
  `{code: {"name", "consumer_cents", "consultant_cents", "points"}}`. Mirrors the existing
  `collect_shade_candidates` shape so the unit tests need neither openpyxl nor xlrd.
- `collect_from_archive(files) -> tuple[dict[tuple[int, int, str], dict], dict[str, list[str]]]` -
  the loop; the second element is the report
  `{"unparsable_name": [...], "unreadable": [...], "no_price_column": [...]}`. Replaces
  `collect_from_xlsx` (renamed: it is no longer xlsx-only).
- `_open_export(path: Path, mode: str, *, encoding: str = "utf-8", newline: str | None = None)` -
  `gzip.open` for a `.gz` suffix, `path.open` otherwise. BOTH keyword arguments are forwarded
  unchanged to either backend - `gzip.open` accepts `encoding` and `newline` in text mode exactly as
  `Path.open` does - so `write_export`'s explicit `newline="\n"` and the utf-8 encoding hold on the
  plain-`.json` branch and on the `.gz` branch alike. Neither branch may fall back to a
  platform-dependent default.

In `scripts/import_master_pricelist.py`:

- `build_catalog_price_records(collected) -> list[dict]` - the 7-key record shape.
  `build_catalog_price_rows` stays, delegating to `build_price_rows(build_catalog_price_records(...))`,
  so its existing test keeps passing without a second mechanism.
- `apply_master_import(session, collected) -> dict[str, int]` - deletes and rebuilds `dictionary`
  wholesale (unchanged rule), then `upsert_price_rows(...)` for the prices. Does not commit.
