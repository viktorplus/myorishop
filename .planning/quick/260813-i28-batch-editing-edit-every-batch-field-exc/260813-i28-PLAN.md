<objective>
`Batch` has NO CRUD today (app/models.py:248-257, D-03: "NO deleted_at and NO
standalone CRUD"). A batch received without an expiry date can never be
corrected; the only workaround is a same-warehouse transfer
(app/services/transfers.py:127-137), which can override ONLY expiry/comment/
cost — never the batch's sale price or its stored location, and a transfer's
own destination batch inherits `price_cents` verbatim (transfers.py:167). The
sale form fills its price FROM the batch (app/routes/sales.py:228-232), so
fixing the product card does not help either. Reported by the user from live
production use.

This plan adds ONE new write to `Batch`: an operator-facing edit of
`name`/`expiry`/`location`/`comment`/`price_cents`/`cost_cents`. Per the
user's locked decision, `quantity` stays read-only ("Количество только через
списание" — shown as read-only text + a link to Списание) and `warehouse_id`
stays read-only (shown as read-only text + a link to Перемещение) — both are
untouchable through this form because `Batch.quantity` is a cached projection
of `SUM(operations.qty_delta)` (models.py:280-282) and editing it directly
would desync stock from the append-only ledger and from profit figures.

Purpose: let an operator fix a batch's real-world data (missing expiry, wrong
sale price, mislabeled location) without a workaround transfer or an
unfixable card.

Output: `update_batch` service + desktop (`/batches/{id}/edit`) and mobile
(`/m/batches/{id}/edit`) edit routes, reachable from four entry points
(desktop product batch table, desktop+mobile `/reports/expiry`, mobile
product detail), plus `?code=` prefill added to `/writeoff` and `/m/writeoff`
(mirroring `/m/corrections`) so the read-only Остаток/Склад rows can link
straight into Списание/Перемещение with the product code pre-filled.
</objective>
