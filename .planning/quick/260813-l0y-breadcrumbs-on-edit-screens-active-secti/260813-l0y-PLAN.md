<objective>
Two operator-reported gaps in live use. PART 1: none of the six edit/detail
screens (desktop `batch_form.html`/`product_form.html`/`customer_form.html`/
`warehouse_form.html`, mobile `batch_edit.html`/`search_product_detail.html`)
show which specific object is open — the h1 only says the ACTION ("Редактирование
партии"), never the object, and a product can have several batches that
differ only by expiry/price. PART 2: both navs (`base.html`, `mobile_base.html`)
mark the active section with a bare `startswith` on the section's OWN prefix,
so every nested screen (`/batches/{id}/edit`, `/receipts/new`, `/m/search`,
`/returns`, `/categories`, `/warehouses`, etc.) highlights NOTHING — the
operator loses the "which section am I in" cue exactly where it matters most.

Purpose: restore navigational context on the screens where an operator is
most likely to be several clicks deep and least sure where they are.

Output: a shared `partials/breadcrumbs.html`, a shared `nav_section()`
path→section table (one source read by both bases), breadcrumb trails +
object-identity lines on the six locked-scope screens, and a corrected
active-highlight on both navs for every nested screen in the Товары/История
groupings.
</objective>
