## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser form POST → service validation → ledger write | Untrusted `op_date` text crosses into a stored ledger column and back into a template |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-16 | Tampering | `op_date` reaching SQL | mitigate | Parsed by `parse_op_date` with `date.fromisoformat`, re-serialised with `.isoformat()`, bound as an ORM parameter. `max=` is a browser convenience, never the guard — the server refuses regardless (the mobile shells prove it, where `max` is inert) |
| T-33-17 | Tampering | XSS via the echoed value on a 422 | mitigate | Jinja autoescaping; the value is never rendered with `\|safe`, and the RU error is a fixed module constant, not operator text |
| T-33-18 | Repudiation | An operator-supplied date overwriting the audit timestamp | mitigate | `record_operation` still stamps `created_at=utcnow_iso()`; `business_date` is a separate, trigger-guarded column |
| T-33-28 | Tampering | A batch auto-named with today while its receipt line reads a back-date | mitigate | D-24: the business date is resolved before `receipts.py:208`. Existing names are snapshots and are not migrated |
| T-33-SC | Tampering | npm/pip/cargo installs | accept | No package installed; `pyproject.toml` untouched |
</threat_model>
