<objective>
Two facts about the live s1 server cannot be read from this repository, and one of them **gates
writing the migration**. Migrations may never import application modules (WR-06, stated verbatim in
`alembic/versions/0026_*.py:27-29` and `app/db.py:20-22`), so the backfill's timezone must be a
literal constant baked into `0027`'s source text — the way `0024:30` declares
`_DEFAULT_CURRENCY = "RUB"` instead of importing `app.core.DEFAULT_CURRENCY`. If that literal does
not match what s1 actually runs, the tz-correct backfill produces off-by-one business dates across
the server's entire history and DATE-07's byte-identity criterion fails on production data while
passing in CI.

Purpose: answer V13 and V14, and write the rollout runbook (LOCKED ordering constraint 5) BEFORE the
migration exists. This plan is `autonomous: false` on purpose — the answers live on a remote host
that CLAUDE.md PC-9 puts out of bounds for autonomous action.
Output: `.planning/phases/33-back-dated-operations/33-ROLLOUT.md`.
</objective>
