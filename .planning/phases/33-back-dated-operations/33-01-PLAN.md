<objective>
SYNC-10 / SYNC-11, server half. Close the one-directional, silent data-loss window that this
phase's own migration would otherwise open across a self-updating client fleet: `merge._ledger_row`
(`app/services/merge.py:460`) projects an incoming batch through the RECEIVER's columns, so a client
that self-updates ahead of the s1 rebuild pushes `business_date`, the server drops the key, returns
200, and `app/services/sync_client.py:384-393` stamps `synced_at` — permanent and unrecoverable
behind a success response. Verified by execution (`33-RESEARCH.md` V2: `parse_exchange` keeps the
unknown key, `_ledger_row` projects it away, `apply_merge` reports `cash_inserted=1`).

Purpose: this is LOCKED ordering constraint 1 — SYNC-10..13 land BEFORE the migration, as the first
plans of the phase. Nothing here is polish.

`app/routes/sync.py`, and `tests/test_sync_schema_gate.py` carrying VA-1 and VA-2.
