behaviours as regression tests so nobody "fixes" them later.

The hole (`33-RESEARCH.md` NC-3): `tests/test_append_only_cursor.py` compares models ↔ constants
(`:246-258`) and constants ↔ `app/db.py` DDL (`:261-290`). **Nothing compares `app/db.py` ↔ the
migrations** — which is exactly the drift migration `0026` exists to patch after the fact. And V3
confirmed `tests/conftest.py:27` and `:294` both build with `Base.metadata.create_all`, so the
existing trigger-liveness coverage is not migration-proving.

SYNC-12 is a PINNING test, not a fix (`33-RESEARCH.md` CF-2 / V1): SQLAlchemy 2.0.51 drops
`None`-valued keys from the emitted INSERT and substitutes the column default, so
`CashMovement.currency` is NOT a live bug and `merge._ledger_row` needs no repair. Adding a
`None`-filter there would be a second mechanism (CLAUDE.md PC-6) AND would break DATE-08 by
suppressing the deliberate NULL a pre-update client must produce (AP-3).

Purpose: LOCKED ordering constraint 1 — these land before the migration, so migration `0027` ships
into a suite that can already prove it.
Output: `tests/test_migrations.py` (VA-5, VA-6, VA-7), the `alembic_engine` fixture, and two new
`tests/test_merge.py` cases (VA-3, VA-4).
