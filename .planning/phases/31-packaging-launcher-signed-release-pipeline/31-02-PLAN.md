<objective>
Implement PKG-03 — the single highest-risk change of the phase. Root the operator's SQLite DB,
`.env`, per-install `secret_key`/`device_id`, and `backups/` under an ABSOLUTE data directory
supplied by the launcher via one env var (`MYORISHOP_DATA_DIR`, default `"data"`), so the
operator's data lives as a physical SIBLING of the swappable application directory and an
over-the-top app-dir swap can never reach or destroy it (ROADMAP Phase 31 criterion 3;
STATE.md "Data preservation by physical layout, not careful code").

Purpose: Without this seam, `backup_dir` is CWD-relative `"backups"` and — under packaging where
CWD is `app\` — backups would land INSIDE the swappable dir and be destroyed on the first update,
wiping the operator's only ledger copy (RESEARCH Pitfall 2). This is the foundation the launcher
and build depend on.
Output: A surgical edit to `app/config.py` that turns `tests/test_packaging.py` PKG-03 assertions green.
</objective>

<artifacts_produced>
Artifacts this phase produces (introduced/changed by THIS plan):
- Modified `app/config.py`: a module-level `_DATA_DIR = Path(os.environ.get("MYORISHOP_DATA_DIR", "data")).resolve()` and the rerouting of `env_file`, `db_path`, and `backup_dir` under it.
- New env var contract: `MYORISHOP_DATA_DIR` (absolute data-dir root, exported by the Plan-03 launcher; default `"data"` preserves dev/run.bat behavior byte-identically).
- No new symbols beyond `_DATA_DIR`; `secret_key`/`device_id` resolution (`_resolve_local_identity`) is unchanged and follows `Path(db_path).parent` for free.
</artifacts_produced>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| launcher env → app | `MYORISHOP_DATA_DIR` is supplied by the trusted launcher (same-user process); the app resolves it once and confines all data I/O under it |
| app dir swap → data dir | The swap replaces app\; data\ is a physical sibling the swap cannot reach — enforced by absolute rooting here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-05 | Tampering | MYORISHOP_DATA_DIR resolution | mitigate | `.resolve()` normalizes the launcher-supplied path to an absolute canonical dir; the app never joins untrusted client input into data paths (the value comes from the same-user launcher, not the network). Confinement of *staged*/*pending* paths is Plan 03 |
| T-31-06 | DoS (data integrity) | backup_dir placement | mitigate | Absolute backup_dir under data\ guarantees VACUUM-INTO snapshots survive an over-the-top app-dir swap (the pre-update anchor for Plan 03 rollback) |
</threat_model>
