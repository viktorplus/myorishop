<objective>
Close GAP-1 (blocker): a fresh install can never reach the login page because nothing on the
first-run path runs `alembic upgrade head`. `launcher/__main__.py:101-113` `main()` calls
`app_process.start()` with no migration step, and `adapters.migrate` is reachable ONLY from
`apply_update` (line 86) — i.e. exclusively the update-swap path. The DB file is created without a
schema and every page returns HTTP 500 (`no such table: users`).

`run.bat:12-17` already defines the contract for the dev path: run `alembic upgrade head`, and if it
fails, print a message and do NOT start the server. This plan gives the packaged path the same
contract by wiring the ALREADY EXISTING `adapters.migrate` into the boot sequence — no second
migration mechanism is written.

Purpose: PKG-01 says the operator launches the distribution and reaches a working browser UI. Today
that is false for every fresh install. This is also the gate that makes the Phase 31 UAT re-runnable.
Output: `boot()` in `launcher/__main__.py`, three fast regressions in `tests/test_launcher.py`, and
one skip-gated real-dist first-run test in `tests/test_packaging.py`.
</objective>

<interfaces>
Contracts this plan consumes (already shipped, do not redefine):
- `launcher.adapters.migrate(paths) -> None` (adapters.py:86-101) — runs `app\python.exe -m alembic
  upgrade head` with `cwd=paths.app` and `MYORISHOP_DATA_DIR=<abs paths.data>`, `check=True`, so a
  non-zero exit raises `subprocess.CalledProcessError`.
- `launcher.adapters.AppProcess(paths)` with `.start()` / `.stop(timeout=30.0)` (adapters.py:29-83) —
  owns the child PID; `start()` spawns `app\python.exe -m uvicorn app.main:app --host 127.0.0.1
  --port <adapters._PORT>`.
- `launcher.__main__.build_paths(launcher_dir=None) -> Paths` (__main__.py:31-47) and
  `run_once(paths, app_process, *, migrate, health_ok, backup_restore) -> bool` (__main__.py:50-93).
- `launcher.swap.Paths(app, app_prev, staged, app_failed, install_root=None, data=None)` (swap.py:33-48).
- `alembic/env.py:28-31` already does `Path(db_file).parent.mkdir(parents=True, exist_ok=True)` for a
  sqlite URL, so `alembic upgrade head` creates a missing `data\` itself — the boot step must NOT
  add a second mkdir.

Interface this plan introduces (Plan 31-07 and 31-08 build on it):
- `launcher.__main__.boot(paths, app_process, *, migrate=adapters.migrate) -> None`
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| launcher → data\ schema | The boot migration writes the operator's real DB schema before any request is served |
| launcher → app\ child | The app child is started only after the schema is at head |
| operator → console | The only channel that reports a failed migration on a packaged install |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-06 | DoS (data integrity) | boot-time migration | mitigate | The app is started ONLY after `alembic upgrade head` exits zero; a partially-migrated or unmigrated schema never serves traffic, so no request can write against a schema the code does not expect |
| T-31-07 | DoS (availability) | failed boot migration | mitigate | NEW. `boot()` aborts with `SystemExit(1)` and a stderr message instead of starting anyway or silently retrying; the console window the Start-Menu shortcut opens (Plan 31-08) is where the operator sees it |
| T-31-04 | Tampering | migration source | mitigate | The boot migration runs ONLY the alembic tree bundled inside `app\` by `build_release.assemble_onedir` (Pitfall-5 count gate) — no network, no marker, no operator-supplied path is involved |
| T-31-05 | Tampering | data-dir path | mitigate | `MYORISHOP_DATA_DIR` is set by `AppProcess._env`/`adapters.migrate` from the launcher-derived absolute `paths.data`; the boot path adds no new externally-supplied path input |
</threat_model>
