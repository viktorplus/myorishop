<objective>
Build PKG-01 and the build-side of PKG-05/PKG-02: `build_release.py`, the repeatable assembler
that turns the git+uv checkout into a self-contained Windows onedir distributable (Python 3.13
embeddable runtime + vendored wheels + app source + alembic + launcher), computes the release
SHA-256 and writes the signed-manifest payload, asserts the tag↔version contract, and generates
the per-user Inno Setup script (ROADMAP Phase 31 criteria 1, 2, 5).

Purpose: The embeddable-package onedir (NOT PyInstaller, NOT a single-file exe) is the locked
strategy — genuine Microsoft-recognized python.exe, lowest AV/SmartScreen surface, and Alembic
`versions/`, templates and static ship as plain copied files with zero hidden-import archaeology
(RESEARCH Pattern 1, Anti-Patterns). `build_release.py` is the single SUT for both the CI pipeline
(Plan 05) and the installer, and the manifest it writes is what the offline minisign key signs.
Output: `build_release.py` turning the PKG-01 layout and PKG-05 manifest assertions in
`tests/test_packaging.py` + `tests/test_release_verify.py` green.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| python.org / PyPI → build | The embeddable zip + wheels are fetched at build time; pinned + hash-verified before assembly |
| build output → release | The onedir archive is the asset the manifest binds and the offline key later signs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Spoofing (user-trust) | SmartScreen "unknown publisher" | accept | Ship unsigned per PKG-02; keep AV/SmartScreen surface LOW by using the genuine Python embeddable (NOT PyInstaller's self-extracting bootloader, a documented AV trigger) — RESEARCH Anti-Patterns |
| T-31-03 | Tampering | release archive integrity | mitigate | write_manifest binds version + archive SHA-256; the tamper-detection helper re-hashes; the offline minisign signature over manifest.txt is added in Plan 05 |
| T-31-SC | Tampering (supply chain) | embeddable zip + vendored wheels | mitigate | fetch_embeddable verifies the embeddable SHA-256 against python.org; wheels are the ALREADY-locked uv.lock deps (no new package added this phase — RESEARCH Package Legitimacy Audit clean); wheels built Windows-native (Pitfall 7) |
| T-31-05 | Tampering | version tag input | mitigate | assert_tag_matches_version validates the tag against ^v1\.\d+$ before acting (V5) and fails on drift from __version__ |
</threat_model>
