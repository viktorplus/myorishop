<objective>
Ship the PKG-05 release pipeline and the PKG-02 installer/SmartScreen documentation: a
tag-triggered GitHub Actions workflow that builds the distributable on a Windows runner and
publishes a DRAFT release (archive + SHA-256 + manifest.txt), the offline-signing runbook that
reconciles "the pipeline publishes a signature" with "the secret key is OFFLINE" via a two-stage
build-in-CI / sign-offline-attach flow, the vendored public key the client verifies against, and
an automated minisign round-trip proving verify passes and tamper fails (ROADMAP Phase 31 criteria
2 and 5).

Purpose: The offline minisign secret key must NEVER become a GitHub Actions secret (RESEARCH
Pattern 5 / Anti-Patterns) — CI builds and drafts everything, a human on the offline machine signs
`manifest.txt` and publishes. Phase 32's self-update verifies against the pubkey vendored here.
Output: `.github/workflows/release.yml`, `docs/RELEASE.md`, `app/minisign.pub`, and a CI minisign
verify step turning the remaining `tests/test_release_verify.py` assertions green.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| offline key machine → GitHub | The minisign SECRET key lives only on the offline machine; only the signature (.minisig) and the public key cross into GitHub |
| GitHub Actions → release assets | CI builds + drafts but cannot sign; a human attaches the offline signature and publishes |
| release assets → client | Client verifies SHA-256 + Ed25519 (Phase 32) against the vendored app/minisign.pub |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-02 | Info Disclosure / Spoofing | minisign secret key | mitigate | Two-stage flow: key NEVER enters CI (no repo secret); CI drafts, human signs offline and publishes (RESEARCH Pattern 5). .gitignore blocks the secret-key filename |
| T-31-03 | Tampering | release archive / manifest | mitigate | manifest.txt binds version + archive SHA-256; the offline Ed25519 minisign signature over manifest.txt is the tamper gate; CI round-trip proves verify passes and tamper fails |
| T-31-01 | Spoofing (user-trust) | unsigned installer / SmartScreen | accept | Documented one-time RU «Выполнить в любом случае» step; code-signing cert deferred (PKG-02); AV surface kept low via the embeddable onedir (Plan 04) |
| T-31-SC | Tampering (supply chain) | minisign binary in CI | mitigate | Install the official jedisct1 minisign; the throwaway round-trip key is generated per-run in tmp, never the production key |
</threat_model>
