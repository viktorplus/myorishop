# Докачать недостающие прайс-листы и пополнить справочник

**Area:** tooling
**Created:** 2026-08-31
**Status:** pending

## Problem

Справочник (`dictionary`) пополняется из архивных прайс-листов Oriflame в
`catalogs/price_lists/`. Набор неполный — часть периодов отсутствует, поэтому
часть кодов остаётся без названия. На 2026-08-31 таких кодов 34 только по
описи склада «Офис».

Источник ссылок: https://webori.ru/katalog/price-list-oriflame/ — строки вида
`<li>№11 2026 (даты): <a href="https://disk.yandex.ru/i/...">xls</a></li>`.
Страница покрывает только 2020–2026; за 2013–2019 ссылок на ней нет.

Чего не хватает локально:

| Период | Причина |
|---|---|
| `03-2022`, `01-2023` | ссылка на Яндекс.Диске отдаёт 404 — нужен другой источник |
| `08-2016`, `12-2019`, `14-2019` | на странице webori этих лет нет |
| `12-2026` | на момент проверки без xls (каталог ещё идёт) |
| `12-2013.xls` | файл на диске битый: `IndexError` при чтении, нужен повторный скачок |

## Solution

1. Найти источник для периодов, которых нет на webori (архивы 2013–2019,
   протухшие ссылки 2022–2023). Кандидаты: `webori.ru/price-ru/` — там есть
   «Поиск по коду», «История цен», «Сравнить цены»; возможно, отдаёт названия
   по коду напрямую и закрывает задачу без прайс-листов.
2. Докачать файлы в `catalogs/price_lists/` под именем `NN-ГГГГ.xls[x]`.
3. Переиндексировать и добавить в справочник только отсутствующие коды —
   существующие записи не менять.

Готовые скрипты этой сессии (перенести в репозиторий при выполнении):
- парсер страницы + загрузка через публичный API Яндекс.Диска
  (`cloud-api.yandex.net/v1/disk/public/resources/download?public_key=...`);
- индексатор прайсов код→название с разбором секций и групп оттенков.
