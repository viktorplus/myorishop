# Phase 32 — UI Design Contract

> Visual and interaction contract for the In-App Secure Self-Update surface. Generated by gsd-ui-researcher (autonomous mode), verified by gsd-ui-checker.
>

Every spacing / type / colour value below is REUSED verbatim from `app/static/style.css` and the established conventions encoded in the Phase 2, 29 and 30 UI-SPECs. New work is limited to *interaction contracts* and *Russian copy* for the update surface inside the existing Настройки page and the existing header version chip.

## Surfaces In Scope

This phase's UI is deliberately minimal and lives entirely inside the **admin-gated Настройки page** (`app/templates/pages/settings.html`) plus the **existing header version chip** (`base.html:40`). Three surfaces:

| # | Surface | Host | Notes |
|---|---------|------|-------|
| S1 | **Update-available notice** — new version + release notes, «Обновить и перезапустить» (primary confirm) + «Позже» (defer) | Настройки page, top of an «Обновление приложения» section | Notify-and-confirm — **never** silent auto-apply (UPD-03). Populated by the startup check (UPD-01) and by the manual check (UPD-07). |
| S2 | **Manual check control** — «Проверить обновления» button + its result states (checking / up-to-date / update-available / offline-or-error) | Настройки, «Обновление приложения» section | On-demand check (UPD-07), independent of the startup check. |
| S3 | **Applying / outcome states** — the transient "applying / restarting" state and the failure→rollback / verification-failed messages | Настройки (applying partial) + header version chip | Header `.app-version` chip already reflects `APP_VERSION` = installed release on each process start (UPD-05); no chip markup change. |

**Out of scope (do not redesign):** the app-wide `<nav>`, the online-sync header partial (Phase 29), the auto-sync settings form, any mobile UI, the launcher swap/rollback internals. The whole update surface is **admin-only** (it lives in Настройки, already gated by `require_role("administrator")` + the `{% if current_user.role == "administrator" %}` nav-hide) and is a **hard no-op on the PostgreSQL server** (UPD-06) — on the server the «Обновление приложения» section is not rendered at all.

## Copywriting Contract

All user-facing strings are **Russian** (project convention); versions render as `1.{N}` (integer-counter scheme, UPD-05). Times, where shown, use the existing `| local_dt` Jinja filter (Europe/Moscow, `дд.мм.гггг чч:мм`).

### S1 — Update-available notice (UPD-03)

| Element | Copy (RU) | Notes |
|---------|-----------|-------|
| Section heading (`h2`) | `Обновление приложения` | The «Обновление приложения» section in Настройки |
| Notice heading | `Доступно обновление` | Amber attention notice |
| Version line | `Установлена версия {current}. Доступна версия {latest}.` | e.g. `Установлена версия 1.15. Доступна версия 1.16.`; both are the integer-scheme strings; `latest` comes from the **signature-verified manifest**, never the git tag (UPD-02/05) |
| Release-notes sub-label | `Что нового` | 14px caption above the notes body |
| Release-notes body | *(GitHub release `body`, autoescaped plain text)* | If empty: show `.muted` `Примечания к выпуску отсутствуют.` |
| Primary CTA (confirm) | `Обновить и перезапустить` | Accent primary button; the click IS the explicit confirmation (UPD-03) — no second modal |
| Defer affordance | `Позже` | Secondary — a `.muted` link/button that dismisses the notice for this session; never auto-applies |
| Pre-apply reassurance (`.muted`, near the button) | `Перед обновлением будет создана резервная копия базы данных. При сбое приложение вернётся к текущей версии.` | Communicates the UPD-04 backup + matched-pair rollback so the operator confirms with confidence |

### S2 — Manual check control (UPD-07)

| Element | Copy (RU) | Notes |
|---------|-----------|-------|
| Check button | `Проверить обновления` | Accent primary button (mirrors the sync form's `Сохранить` idiom) |
| In-flight (hx-indicator) | `Проверка обновлений…` | Muted; shown during the request, replaces/adjoins the button (no spinner) |
| Result — up to date | `У вас последняя версия (1.{N}).` | Muted caption |
| Result — update available | *(render the S1 notice)* | The manual check that finds a newer version renders the same S1 notice |
| Result — offline / check failed | `Не удалось проверить обновления. Проверьте интернет-соединение и попробуйте снова.` | Muted caption — **only for the explicit manual check**; the startup check stays silent when offline (UPD-01) |

### S3 — Applying + outcome states

| Element | Copy (RU) | Notes |
|---------|-----------|-------|
| Applying / restarting | `Идёт обновление. Приложение перезапустится автоматически — дождитесь перезапуска и обновите страницу.` | Muted; shown after «Обновить и перезапустить». The launcher stops the app during the swap, so the browser will briefly lose connection — this copy sets that expectation |
| Verification failed | `Обновление не прошло проверку подлинности и было отменено. Ничего не установлено.` | `.error-block`; UPD-02 hard-gate failure — nothing was applied |
| Apply / migration failure → rollback | `Не удалось установить обновление. Восстановлена предыдущая версия, ваши данные в безопасности.` | `.error-block`; UPD-04 matched-pair rollback reassurance |
| Success (after restart) | *(no dedicated message needed — the header chip now shows the new `1.{N}`)* | UPD-05: `APP_VERSION` re-read on process start; optionally a `.muted` `Обновлено до версии 1.{N}.` after the operator returns |

### Destructive actions

**None that destroy data.** «Обновить и перезапустить» swaps code and restarts the app, but a pre-update `VACUUM INTO` backup is taken and any failure rolls back to the previous code + pre-update DB as a matched pair (UPD-04). It is therefore a **significant-but-safe confirm action**, styled with the **accent primary** button (never `button.danger` red), accompanied by the reassurance caption above. Do **not** add a separate destructive confirmation modal — the notify-and-confirm banner plus the explicit button click IS the confirmation (UPD-03).

## Surface Contracts (Interaction & Layout)

**Placement:** everything lives in a new `«Обновление приложения»` section inside `pages/settings.html`, below the existing sync section, mirroring the sync-form idiom (`<h2>` + `form.stacked-form` + `.field` + `.form-actions` + `<button>`). CSRF is carried by the existing `<body hx-headers>` line in `base.html:35`. The section is rendered **only** when `db.engine.dialect.name == "sqlite"` (UPD-06 — the PostgreSQL server never shows it).

### S2 — Manual check (the entry interaction)
- `«Проверить обновления»` is a `<button>` inside a `<form class="stacked-form" hx-post="/settings/update/check" hx-target="#update-panel" hx-swap="innerHTML" hx-indicator="#update-inflight">`.
- The response swaps a `#update-panel` partial into one of: up-to-date caption, the S1 notice, or the offline/error caption. Always returns **200** with a partial (never a 5xx page) — a check failure is a caption, not an error page, consistent with the sync surface's non-blocking posture.
- In-flight `«Проверка обновлений…»` shown via `hx-indicator="#update-inflight"` + the project's `.htmx-indicator` opacity rule (no spinner graphic).

### S1 — Update-available notice
- A `#update-panel` partial: amber attention notice (`background:#fef9e7; border:1px solid #b45309; border-radius:4px; padding:16px;` — reusing the `.price-below` token pair + existing radius; NO new class required, or a small `.update-notice` class using only those existing values).
- Contains: heading `Доступно обновление`, the version line, the `Что нового` sub-label + autoescaped notes body, the reassurance `.muted` caption, then a `.form-actions` row with the accent `«Обновить и перезапустить»` button (`hx-post="/settings/update/apply"`) and the `«Позже»` muted dismiss control (`hx-post="/settings/update/dismiss"` or a client-side hide — planner discretion).
- **Startup-detected update:** the same `#update-panel` renders the notice on first paint of Настройки when the startup check (UPD-01) has already flagged a newer version — no separate widget, no header banner. Rationale: the update path is admin-only and Настройки is the admin's home for it; a header banner would leak an admin-only affordance onto every operator page.

### S3 — Applying + outcome
- «Обновить и перезапустить» → `hx-post="/settings/update/apply"` swaps `#update-panel` to the **applying** partial: the muted `Идёт обновление…` caption. The app stages the verified bundle + writes `pending.json`, then the launcher stops/swaps/migrates/restarts — the browser loses the connection mid-request, which the copy pre-explains ("дождитесь перезапуска и обновите страницу").
- On a verification failure (UPD-02) the apply route returns **before** staging anything and swaps `#update-panel` to the `.error-block` `Обновление не прошло проверку подлинности…` — nothing was written, the app keeps running.
- On a post-restart rollback (UPD-04), when the operator reopens Настройки the panel shows the `.error-block` rollback reassurance and the header chip still shows the **previous** `1.{N}` (proving data + code reverted as a pair).
- **Header version chip:** unchanged markup (`<span class="app-version muted">MyOriShop v{{ APP_VERSION }}</span>`, base.html:40). After a successful swap+restart, `APP_VERSION` (re-read from `app/__init__.py __version__` on process start) shows the new `1.{N}` — this is the visible proof of UPD-05, requiring no new UI element.

## Accessibility & Security Notes

- **No colour-only meaning** — every state carries its Russian text string (WCAG 1.4.1); versions are shown as numbers.
- **Focus** — the check and apply buttons reuse the existing `:focus-visible { outline: 2px solid #2563eb }` ring (style.css:223); never suppress it.
- **Non-blocking** — the startup check never blocks or delays launch (offline = silent no-op, UPD-01); the manual check returns a caption, never a 5xx page.
- **Autoescaping / untrusted content** — the release-notes `body`, `tag_name`/version, and any GitHub JSON field are **untrusted** and must be rendered autoescaped (never `|safe`, never raw HTML/markdown). Validate the version shape (`^1\.\d+$`) before display; never echo raw server/error bytes or a stack trace into the panel (mirrors the sync surface's fixed-string errors, T-29-07). The trusted version for the anti-downgrade comparison comes from the **signature-verified manifest**, not the mutable tag.
- **No motion** — no spinner/progress-bar/animation asset anywhere; the "checking" and "applying" states are muted text, consistent with the shipped sync in-flight indicator.
