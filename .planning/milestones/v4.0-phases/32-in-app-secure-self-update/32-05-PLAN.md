admin-only «Обновление приложения» section inside Настройки, the notify-and-confirm
notice, and the one-shot offline-safe startup check. This is the last wave; it
turns the tested trust core (Waves 03/04) into the shipped UPD-01/03/07 surface
and confirms the UPD-05 header chip + UPD-06 render gate.

a SINGLE non-blocking task (periodic re-check is deferred), never awaited before
`yield`, so an offline launch is never blocked (UPD-01).

Output: the settings route group + section + `#update-panel` partial + the
lifespan startup check.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub release fields -> rendered HTML | `body`, `tag_name`, version are untrusted and reach the admin's browser — must be autoescaped and shape-validated |
| startup network check -> app launch | The check must never block or crash an offline launch |
| dialect -> UI render | The update UI must not exist on the PostgreSQL server |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-01 | Tampering / Elevation | untrusted release notes/version rendering | mitigate | `body`/`tag_name`/version rendered autoescaped (never `|safe`); version shape `^1\.\d+$` validated before display; no raw server/error bytes echoed (ASVS V5, T-29-07) |
| T-32-10 | Denial of Service | startup update check | mitigate | Single non-blocking `asyncio.create_task`, offloaded via `anyio.to_thread.run_sync`, broad-guarded, never awaited before `yield` (ASVS V1) |
| T-32-09 | Denial of Service | update UI on the server | mitigate | The «Обновление приложения» section is `{% if not is_server_db %}`; check_for_update dialect-no-ops (ASVS V1) |
| T-32-03 | Tampering / Information Disclosure | manual check route | mitigate | Route always returns a 200 caption, never a 5xx / stack trace; failures are fixed Russian strings (ASVS V5) |
| T-32-SC | Tampering | pip installs | accept | No package install in this plan; `cryptography` vetted in Plan 02 |
</threat_model>
